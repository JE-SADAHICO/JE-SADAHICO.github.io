2025.10

Tekla 매크로

모델의 면과 방향을 직접 해석 · 모델 체크 자동화

표를 가공하는 대신 BIM 모델에 직접 접근한다 엑셀을 벗어나 처음으로 C#을 사용해 BIM 소프트웨어의 API를 다루기 시작했습니다. 내보낸 데이터를 받아 가공하던 방식에서, 모델 안의 3D 형상을 직접 읽고 계산하는 방식으로 바뀌었습니다.
2026.01

독립 애플리케이션

기능 통합 · 배포와 업데이트 관리

코드를 나눌 수 없는 구조 매크로 형태로는 파일 분리가 불가능해, 기능이 늘어날수록 코드 관리가 어려워졌습니다. 독립 애플리케이션으로 전환한 이유입니다.
막힐 때마다 먼저 그것이 방법의 문제인지 도구의 한계인지를 판단했고, 도구의 한계라면 한 단계 위의 도구를 찾아 익혔습니다.

12R&D

DRAW변경의 의미에 맞는 후처리를, 자동으로.

○ R&D · 도면 후처리의 판단과 실행 자동화

도면의 배치가 바뀐 것과,
부재의 형상·위치가 바뀐 것은
다릅니다.

기존 도면 겹쳐보기에서는 도면의 배치만 바뀐 경우와, 부재의 형상·위치 변경으로 도면이 갱신된 경우가 모두 화면상의 차이로 나타났습니다.

작업자는 차이의 원인을 다시 확인하고, 필요한 후처리와 실행 순서를 직접 정해야 했습니다.

DRAW는 반복적인 확인과 공정 선택을 줄이고, 변경 상황에 맞는 후처리를 연결하기 위한 연구입니다.

  • 반복적인 확인 작업 감소변경 이유를 다시 확인하는 부담을 줄입니다.
  • 필요한 후처리 선택상황에 맞는 작업과 실행 순서를 정합니다.
  • 기존 기능과의 연계선택한 작업을 PACK의 기능으로 처리합니다.

13Architecture

Tekla API와 계산 엔진의 분리

BIM 연동과 계산을 분리해, 검증은 독립적으로 실행은 통합적으로

계산은 따로 테스트하고,
모듈의 실행은 함께 관리합니다.

기존에는 계산 로직을 수정할 때마다 BIM 프로그램에서 실제 모델을 확인해야 했습니다. 계산 엔진을 분리한 뒤에는 저장된 테스트 데이터로 계산 결과를 자동 검증할 수 있게 됐습니다.

  1. 독립 자동 테스트BIM을 실행하지 않고 저장된 사례를 반복 검증
  2. 다른 BIM으로의 확장 기반프로그램별 연동부를 통해 계산 엔진 재사용
  3. 중앙 실행·상태 관리작업 요청과 진행·완료·오류 상태를 한곳에서 관리
